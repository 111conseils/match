<analysis>**original_problem_statement:**
The user is a recruiter who needs a private web application to manage candidates and job positions. The primary goal is to get automatic matches between candidates and jobs based on job title and geographic location. The user manages many zones and needs a tool to streamline this process.

**PRODUCT REQUIREMENTS:**
1.  **Entities:**
    *   **Candidates:** Manage candidate profiles including name, geographic area (city + radius), job title, salary, availability, source, status, and archives.
    *   **Jobs/Posts:** Manage job listings including the hiring company, job title, location, and whether a formal agreement (convention) is signed. Add contact person and email for the post.
2.  **Core Functionality:**
    *   **Matching:** Automatically match candidates to jobs based on job title and geographic proximity.
        *   Initially, this used a static list of cities, but was later upgraded to use the live French government address API for geocoding all of France.
        *   Matching should be bi-directional (job -> candidates AND candidate -> jobs).
        *   Only show 100% matches.
    *   **Process Tracking:** A candidate can apply for multiple jobs simultaneously. Each application (a process) must have its own status (e.g., CV sent, interview, offer, placed) and potential fee amount.
    *   **Tinder-like Match Interaction:** On the matching page, the user wants to be able to accept or reject a match for a specific candidate/job pair. Rejecting would archive that specific match.
3.  **Data Management:**
    *   **Import:** Allow bulk import of candidates and jobs from Excel files. The system should be flexible with column names.
    *   **Export:** Allow exporting candidates, jobs, and processes to Excel.
4.  **Access & Security:**
    *   The application must be private, accessible only via login/password.
    *   User registration must be disabled, with the user being the sole administrator.
5.  **Branding:**
    *   The application should be named 111MATCHING.
6.  **UI/UX:**
    *   Add an archive system for candidates to hide them from the main pipeline, with filters for active and archived.
    *   Use visual indicators (colors, icons) for statuses like convention signed.

**User's preferred language**: French
